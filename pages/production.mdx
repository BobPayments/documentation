Use produção somente depois que o fluxo completo funcionar com `sk_test_`.

## Checklist antes da troca

- [ ] A chave de API existe somente no backend e não aparece em logs.
- [ ] A criação usa uma `Idempotency-Key` por pedido.
- [ ] Um timeout é repetido com a mesma chave de idempotência.
- [ ] O endpoint de webhook usa HTTPS e valida a assinatura com o corpo bruto.
- [ ] O evento `transaction.paid` libera o pedido uma única vez.
- [ ] Os eventos `transaction.expired`, `transaction.cancelled` e `transaction.refunded` são tratados.
- [ ] Respostas `4xx`, `5xx` e `202` são tratadas.
- [ ] Pagamento e expiração foram testados no sandbox.

## Troque a chave

Substitua a variável de ambiente. A URL e o código da integração continuam iguais.

```bash
# Sandbox
BOB_API_KEY=sk_test_sua_chave

# Produção
BOB_API_KEY=sk_live_sua_chave
```

<Warning>
  Uma chave `sk_live_` movimenta dinheiro real. Se ela vazar, revogue-a no Dashboard e gere outra.
</Warning>

## Monitore as primeiras transações

Confirme estes pontos no Dashboard e nos logs do seu backend:

- a transação criada tem o valor e o projeto esperados;
- o webhook chega e passa pela validação de assinatura;
- o pedido muda de estado uma única vez;
- erros guardam o `type`, o `status`, o `instance` e o horário da requisição;
- logs não contêm chaves, secrets nem dados pessoais desnecessários.

## Trate o HTTP 202

Uma criação pode retornar `202` quando o PIX foi gerado, mas a persistência ainda está em reconciliação. Nesse caso, `data.id` pode ser `null`.

Apresente o `pixCode` e use `externalId` para acompanhar a transação. [Veja os detalhes e a estratégia de repetição](/pages/errors).
