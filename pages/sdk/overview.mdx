A Bob oferece SDKs oficiais em **duas camadas**. Elas resolvem problemas diferentes e costumam ser usadas juntas: uma biblioteca de **servidor** cria a cobrança e verifica webhooks no seu backend; o SDK de **frontend** monta o checkout e tokeniza o cartão no navegador.

<Note>
  Os SDKs de servidor cobrem PIX, cartão (`btk_...` + tokenização) e cripto. O [SDK Checkout](/pages/sdk/checkout) embute a tela no browser. Use apenas métodos **habilitados no projeto**.
</Note>

## Escolha seu SDK

| SDK | Camada | Linguagem / Plataforma | Quando usar |
|---|---|---|---|
| [SDK Node.js](/pages/sdk/node) | Servidor (backend) | Node.js / TypeScript | Criar cobranças, listar transações e verificar webhooks a partir do seu servidor. |
| [SDK PHP](/pages/sdk/php) | Servidor (backend) | PHP | O mesmo, em stacks PHP. |
| [SDK Checkout](/pages/sdk/checkout) | Frontend (navegador) | JavaScript / React | Embutir o checkout da Bob no seu site, tokenizar cartão e conduzir 3DS sem expor os dados brutos do cartão. |

<Note>
  As chaves secretas (`sk_live_`, `sk_test_`) só existem no **servidor**. A criação da sessão de checkout acontece no backend com uma biblioteca de servidor; o SDK Checkout roda no navegador e recebe apenas o `checkoutToken`.
</Note>

## Fluxo típico (servidor + frontend juntos)

```text
Seu backend  ── SDK Node.js/PHP ──>  cria a sessão de checkout (sk_...)
                                      │
                                      └─ checkoutToken ─> seu frontend
Seu frontend ── SDK Checkout ──────>  monta o checkout, tokeniza cartão, conduz 3DS
```

## Não tem SDK para a sua linguagem?

Todas as operações estão disponíveis na REST API — os SDKs são conveniências sobre ela. Consulte a [Referência da API](/pages/pix/create) e chame os endpoints direto do seu backend em qualquer linguagem.
