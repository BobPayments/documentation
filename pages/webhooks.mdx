O pagamento acontece de forma assíncrona. Use `transaction.paid` como a confirmação para liberar o pedido.

## Configure o endpoint

<Steps>
  <Step title="Crie uma rota HTTPS">
    Prepare uma rota pública, como `POST https://api.sualoja.com/webhooks/bob`.
  </Step>
  <Step title="Adicione o webhook no Dashboard">
    Abra **Webhooks**, clique em **Adicionar webhook** e informe a URL.
  </Step>
  <Step title="Use a versão v2">
    Canais novos usam v2. Essa versão envia valores em centavos e protege contra replay.
  </Step>
  <Step title="Guarde o secret">
    Salve o secret do webhook em uma variável protegida, como `BOB_WEBHOOK_SECRET`.
  </Step>
</Steps>

O sandbox envia eventos para o mesmo endpoint. O campo `data.isSandbox` diferencia os testes de produção.

## Valide a assinatura

Use o corpo bruto da requisição. Se o framework converter o corpo para JSON antes da validação, a assinatura pode falhar.

O header `X-Webhook-Signature` tem o formato `t=<unix>,v1=<hmac>`. A assinatura é o HMAC-SHA256 de `timestamp + "." + corpo_bruto`.

Sua validação precisa:

1. Extrair o timestamp e o HMAC do header.
2. Calcular o HMAC com o secret do webhook e o corpo bruto.
3. Comparar as assinaturas em tempo constante.
4. Rejeitar timestamps com mais de cinco minutos.

<CodeGroup>
```javascript Node.js
import crypto from 'node:crypto';

export function verifyWebhook(rawBody, signatureHeader, secret, tolerance = 300) {
  const match = signatureHeader?.match(/^t=(\d+),v1=([0-9a-f]{64})$/);
  if (!match) return false;

  const [, timestamp, received] = match;
  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${timestamp}.`)
    .update(rawBody)
    .digest('hex');

  const receivedBuffer = Buffer.from(received, 'hex');
  const expectedBuffer = Buffer.from(expected, 'hex');
  const fresh = Math.abs(Date.now() / 1000 - Number(timestamp)) <= tolerance;

  return receivedBuffer.length === expectedBuffer.length
    && crypto.timingSafeEqual(receivedBuffer, expectedBuffer)
    && fresh;
}
```

```php PHP
function verifyWebhook(
    string $rawBody,
    ?string $signatureHeader,
    string $secret,
    int $tolerance = 300
): bool {
    if (!preg_match('/^t=(\d+),v1=([0-9a-f]{64})$/', $signatureHeader ?? '', $matches)) {
        return false;
    }

    $timestamp = $matches[1];
    $received = $matches[2];
    $expected = hash_hmac('sha256', $timestamp . '.' . $rawBody, $secret);
    $fresh = abs(time() - (int) $timestamp) <= $tolerance;

    return hash_equals($expected, $received) && $fresh;
}
```
</CodeGroup>

<Warning>
  Valide os bytes originais do corpo. Nunca calcule a assinatura sobre um JSON reserializado.
</Warning>

## Processe o evento

Depois de validar a assinatura, converta o corpo para JSON e trate o evento:

```javascript
if (!verifyWebhook(rawBody, signatureHeader, process.env.BOB_WEBHOOK_SECRET)) {
  return response.status(401).send('invalid signature');
}

const event = JSON.parse(rawBody.toString('utf8'));

if (event.event === 'transaction.paid') {
  await confirmOrderOnce(event.data.transactionId);
}

return response.status(200).send('ok');
```

## Entenda o payload v2

```json
{
  "event": "transaction.paid",
  "apiVersion": "v2",
  "type": "transaction",
  "data": {
    "transactionId": "clx1abc123",
    "externalId": "pedido-001",
    "amountCents": 15000,
    "product": "Pedido 123",
    "paymentMethod": "pix",
    "customerName": "João Silva",
    "isSandbox": true,
    "createdAt": "2026-08-25T14:30:00.000Z"
  },
  "timestamp": "2026-08-25T14:35:00.000Z"
}
```

Use `event` para decidir a ação e `data.transactionId` para deduplicar o processamento.

## Trate os eventos necessários

| Evento | Ação recomendada |
|---|---|
| `transaction.created` | Registrar que a cobrança foi criada |
| `transaction.paid` | Confirmar o pedido uma única vez |
| `transaction.expired` | Encerrar a tentativa e oferecer outra cobrança |
| `transaction.cancelled` | Encerrar a tentativa |
| `transaction.refunded` | Atualizar o pedido como reembolsado |
| `transaction.failed` | Registrar a falha e orientar uma nova tentativa |

## Responda com segurança

- Valide `X-Webhook-Signature` antes de processar o evento.
- Grave ou enfileire o evento antes de responder HTTP `2xx`.
- Deduplique por `transactionId` e tipo do evento.
- Não libere um pedido com base apenas no conteúdo da tela do comprador.
- Registre falhas sem salvar o secret ou dados pessoais desnecessários.

## Migre canais v1

A versão v1 é legada. Ela usa `data.amount` em reais e uma assinatura HMAC simples, sem proteção contra replay. A versão v2 usa `data.amountCents`, inclui `apiVersion: "v2"` e assina também o timestamp.

Atualize o canal para v2 somente depois que o consumidor aceitar o novo payload. Canais novos já usam v2.
