A Bob Payments processa **cartão de crédito** quando o método está **habilitado no projeto**.

<Note>
  O cartão **deve ser tokenizado no navegador**. A sua aplicação e a API só recebem um token opaco `btk_...` — PAN, CVV e validade nunca passam pela API Bob. Veja o [SDK Checkout](/pages/sdk/checkout) e a [Referência](/pages/credit-card/reference).
</Note>

## Escolha o nível de integração

| Nível | Quando usar |
|---|---|
| **Checkout hospedado** | Caminho padrão. Você cria uma sessão e redireciona o comprador para a `checkoutUrl`. |
| **SDK embutível** | Use quando você já tem uma página própria e quer montar o checkout da Bob dentro dela. |
| **API direta (headless)** | Checkouts próprios: crie uma sessão de tokenização, tokenise no browser com Bob.js/Secure Fields e cobre com `transactions.create`. |

## Fluxo recomendado

```text
Cartão no browser
  -> Bob Checkout / Secure Fields (Bob.js)
  -> token btk_... (uso único, por valor)
  -> API Bob (paymentMethod: credit_card + card.token)
  -> nextActionUrl se 3DS · webhook no desfecho
```

O número do cartão, CVV e validade nunca passam pela API Bob.

<Warning>
  Nunca envie cartão bruto para a API Bob. Payloads com PAN, CVV ou validade são rejeitados.
</Warning>

## Checkout hospedado

Envie `credit_card` em `paymentMethods`:

```bash
curl -X POST https://api.payments.bob.company/api/v1/checkout-sessions/ \
  -H "Authorization: Bearer $BOB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amountCents": 25000,
    "items": [{ "name": "Assinatura Pro", "quantity": 1, "unitAmountCents": 25000 }],
    "paymentMethods": ["credit_card", "pix"],
    "successUrl": "https://loja.example.com/obrigado",
    "webhookUrl": "https://loja.example.com/webhooks/bob",
    "webhookVersion": "v2"
  }'
```

A sessão aceita `credit_card` quando o método está habilitado no projeto. Caso contrário, a API informa que o método não está disponível.

## SDK embutível

```tsx
import { BobCheckout } from '@bobpayments/checkout-sdk';

<BobCheckout
  sessionToken={checkoutToken}
  onSuccess={(payment) => navigate(`/orders/${payment.id}`)}
  onError={(error) => showError(error)}
/>
```

Ou sem React:

```typescript
const checkout = await BobCheckout.create({
  sessionToken: checkoutToken,
});

checkout.mount('#bob-payment');
```

O SDK gerencia os campos seguros, emite o token e conduz 3DS quando necessário.

## API direta (tokenização + cobrança)

Para checkouts **próprios** (headless):

1. No servidor, crie uma sessão de tokenização:

```bash
curl -X POST https://api.payments.bob.company/api/v1/card-tokenization-sessions/ \
  -H "Authorization: Bearer $BOB_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "amount_cents": 30000,
    "currency": "BRL",
    "origin": "https://loja.example.com"
  }'
```

Resposta: `id` (`cts_...`), `client_secret` (`cts_secret_...`), `payment_id`, `expires_at` (~10 min).

2. No navegador, monte o Bob.js/Secure Fields com `id` + `client_secret` e obtenha o token `btk_...`.

3. No servidor, cobre:

```bash
curl -X POST https://api.payments.bob.company/api/v1/transactions/ \
  -H "Authorization: Bearer $BOB_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "customer": { "...": "..." },
    "payment": { "amountCents": 30000, "product": "Assinatura" },
    "paymentMethod": "credit_card",
    "card": {
      "token": "btk_...",
      "installments": 3,
      "returnUrl": "https://loja.example.com/retorno-3ds"
    },
    "originDomain": "loja.example.com"
  }'
```

Se o emissor exigir 3DS, a resposta traz `nextActionUrl` (e `nextAction`) — redirecione o portador. A transação fica em `waiting_payment` até o webhook (`transaction.paid` / `transaction.failed`).

Com o SDK de servidor:

```typescript
const cts = await bob.cardTokenizationSessions.create({
  amountCents: 30_000,
  origin: 'https://loja.example.com',
});
// entregue cts.id + cts.clientSecret ao browser → btk_...

const result = await bob.transactions.create({
  customer,
  payment: { amountCents: 30_000, product: 'Assinatura' },
  paymentMethod: 'credit_card',
  card: { token: 'btk_...', installments: 3, returnUrl: 'https://loja.example.com/retorno-3ds' },
  originDomain: 'loja.example.com',
});

if (result.nextActionUrl) {
  // redirecione para 3DS
}
```

O token `btk_...` é de **uso único e por valor**. Recusa ou mudança de total exigem sessão e token novos. Não persista nem logue o `client_secret`.

## Estados públicos

| Status | Significado |
|---|---|
| `paid` | Pagamento aprovado |
| `waiting_payment` | Aguardando autenticação 3DS ou confirmação assíncrona |
| `processing` | Pagamento recebido, aguardando confirmação |
| `refunded` / `cancelled` / `expired` | Desfechos terminais sem aprovação |

Use webhook e/ou consulta de status para confirmar o desfecho financeiro. Não considere apenas o HTTP `201` como confirmação de pagamento.

## O que você configura

1. Habilite cartão para o projeto no Dashboard.
2. Use o checkout hospedado, o SDK Checkout ou a API direta com tokenização no browser.
3. Configure o webhook para receber a confirmação do pagamento.

<Warning>
  Nunca envie credenciais secretas nem dados brutos do cartão para o navegador, para a API Bob ou para repositórios.
</Warning>
