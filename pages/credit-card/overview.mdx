A Bob Payments também processa **cartão de crédito**. Para a maioria das integrações, use o checkout hospedado ou o SDK embutível da Bob. Eles carregam os campos seguros, tokenizam o cartão, conduzem 3DS e escondem o fallback entre gateways.

<Note>
  Para aceitar cartão no checkout, o cartão **deve ser tokenizado no navegador** pelo pacote de checkout da Bob (`@bobpayments/checkout-sdk`). A sua aplicação e a API só recebem um token seguro — PAN, CVV e validade nunca passam pela API Bob. Veja o [SDK Checkout](/pages/sdk/checkout) e a [Referência](/pages/credit-card/reference).
</Note>

## Escolha o nível de integração

| Nível | Quando usar |
|---|---|
| **Checkout hospedado** | Caminho padrão. Você cria uma sessão e redireciona o comprador para a `checkoutUrl`. |
| **SDK embutível** | Use quando você já tem uma página própria e quer montar o checkout da Bob dentro dela. |
| **API direta** | Use apenas em integrações avançadas que já possuem tokenização, conformidade e tratamento de 3DS próprios. |

## Fluxo recomendado

```text
Cartão
  -> Bob Checkout ou @bobpayments/checkout-sdk
  -> tokenização segura
  -> API Bob
  -> rota publicada de credit_card
  -> Stripe Connect
```

O número do cartão, CVV e validade nunca passam pela API Bob. O comprador também não vê Stripe Checkout nem escolhe gateway. A Bob decide a conexão pela rota publicada.

<Warning>
  Nunca envie cartão bruto para a API Bob. Payloads com PAN, CVV ou validade devem continuar sendo rejeitados.
</Warning>

## Checkout hospedado

Para aceitar cartão no checkout hospedado, envie `credit_card` em `paymentMethods`:

```bash
curl -X POST https://api.payments.bob.company/api/v1/checkout-sessions/ \
  -H "Authorization: Bearer $BOB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amountCents": 25000,
    "items": [{ "name": "Assinatura Pro", "quantity": 1, "unitAmountCents": 25000 }],
    "paymentMethods": ["credit_card", "pix"],
    "successUrl": "https://loja.example.com/obrigado",
    "webhookUrl": "https://loja.example.com/webhooks/bob",
    "webhookVersion": "v2"
  }'
```

A sessão exige uma rota publicada para cada método solicitado. Se não existir rota publicada para `credit_card`, a criação falha com `422` e `ERR_INTEGRATION_006`.

## SDK embutível

Use o SDK embutível quando você quer manter o comprador no seu site, mas não quer implementar Stripe.js, tokenização, 3DS ou fallback.

```tsx
import { BobCheckout } from '@bobpayments/checkout-sdk';

<BobCheckout
  sessionToken={checkoutToken}
  onSuccess={(payment) => navigate(`/orders/${payment.id}`)}
  onError={(error) => showError(error)}
/>
```

Ou monte o checkout em uma página sem React:

```typescript
const checkout = await BobCheckout.create({
  sessionToken: checkoutToken,
});

checkout.mount('#bob-payment');
```

O SDK carrega Stripe.js internamente, monta os campos seguros, cria o `PaymentMethod`, envia o token para a API Bob e conduz 3DS quando necessário. O lojista não precisa importar `@stripe/react-stripe-js`.

## API direta avançada

Use a API direta com cartão somente quando você já possui sua própria implementação de tokenização e autenticação 3DS. Nesse modo, o frontend cria um identificador seguro de método de pagamento (`pm_...`) e envia para a Bob apenas esse token, junto com `paymentMethod: "credit_card"`.

O `pm_...` deve existir apenas em memória durante a tentativa. Não salve esse valor em logs, analytics, URL ou banco do checkout.

O cliente da transação não escolhe `connectionId`. Ele informa o método de pagamento e a rota publicada decide qual gateway processa a tentativa.

## Conectar Stripe

O painel conecta uma conta Stripe ao projeto usando Stripe Connect Hosted Onboarding:

```http
POST /api/v1/connection-accounts/stripe/connect
Authorization: Bearer <token>
Idempotency-Key: connect-<request-id>
Content-Type: application/json
```

```json
{
  "alias": "Stripe principal",
  "email": "financeiro@lojista.com",
  "displayName": "Loja Exemplo",
  "country": "BR",
  "feePercentage": 3.9,
  "feeFixed": 100
}
```

A resposta contém `connectionAccountId`, `stripeAccountId` e `onboardingUrl`. Abra `onboardingUrl` em navegação de tela inteira. Links de onboarding da Stripe são de uso único.

No exemplo, `feePercentage` é a taxa percentual da conexão e `feeFixed` é a taxa fixa em centavos.

Se a Stripe chamar a `refreshUrl`, solicite um novo link:

```http
POST /api/v1/connection-accounts/:connectionAccountId/stripe/onboarding-link
Authorization: Bearer <token>
Idempotency-Key: onboarding-refresh-<request-id>
```

A Bob não recebe a Secret Key do lojista.

## Criar e publicar a rota

Uma rota de cartão precisa ter:

- `paymentMethod: "credit_card"`
- pelo menos uma conexão Stripe válida no mesmo projeto
- status `published`

Exemplo de `flowDefinition`:

```json
{
  "alias": "Cartão - Stripe com fallback",
  "paymentMethod": "credit_card",
  "flowDefinition": {
    "version": 1,
    "entryNodeId": "cartoes",
    "nodes": {
      "cartoes": {
        "type": "gateway_group",
        "gateways": [
          {
            "connectionId": "conn_stripe_principal",
            "trafficPercentage": 100,
            "priority": 1
          },
          {
            "connectionId": "conn_stripe_fallback",
            "trafficPercentage": null,
            "priority": 0
          }
        ],
        "onAllFailed": null
      }
    }
  }
}
```

## Fallback

Para cartão, as tentativas são executadas em sequência conforme a rota publicada. Uma recusa elegível ou indisponibilidade do gateway libera a próxima conexão. O comprador recebe uma única resposta final e não vê detalhes das tentativas internas.

Quando o pagamento exigir ação do comprador, como autenticação 3DS, o checkout deve mostrar a autenticação segura, abrir a URL retornada e consultar o status ao voltar. Mostre sucesso somente quando a sessão ou transação estiver `PAID`/`paid`.

## Estados públicos

| Status | Significado |
|---|---|
| `paid` | Pagamento aprovado |
| `waiting_payment` | Aguardando autenticação 3DS ou confirmação assíncrona |
| `failed` | Todas as tentativas elegíveis falharam |
| `pending` | Pagamento criado, mas ainda sem confirmação final |

Use webhook e/ou consulta de status para confirmar o desfecho financeiro. Não considere apenas o HTTP `201` como confirmação de pagamento.

## Webhook Stripe Connect

Configure na plataforma Stripe o endpoint Connect:

```text
POST https://api.seudominio.com/api/v1/webhooks/stripe/connect
```

O endpoint verifica `stripe-signature` com `STRIPE_CONNECT_WEBHOOK_SECRET`, identifica a conta por `event.account` e reconcilia o pagamento da conexão local. Habilite os eventos de `PaymentIntent` e `Charge` no endpoint Connect.

## Configuração da plataforma

```env
STRIPE_SECRET_KEY=sk_live_...
STRIPE_CONNECT_PLATFORM_SECRET_KEY=sk_live_...
STRIPE_PUBLISHABLE_KEY=pk_live_...
STRIPE_CONNECT_WEBHOOK_SECRET=whsec_...
```

`STRIPE_CONNECT_PLATFORM_SECRET_KEY` pode reutilizar `STRIPE_SECRET_KEY` em instalações legadas, mas produção deve usar uma chave de plataforma explícita. `STRIPE_PUBLISHABLE_KEY` é pública e pode aparecer no payload público do checkout. Nenhuma `sk_...` pode ser enviada ao navegador.
