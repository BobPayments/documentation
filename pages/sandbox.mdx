Use uma chave `sk_test_` para criar transações isoladas de produção. A URL e o contrato da API não mudam.

```bash
BOB_API_KEY=sk_test_sua_chave
```

## Escolha o resultado pelo valor

Os dois últimos dígitos de `amountCents` controlam o resultado automático:

| `amountCents` | Resultado no sandbox |
|---|---|
| Termina em `00`, como `10000` | Muda para `paid` em cerca de 5 segundos |
| Termina em `01`, como `10001` | Muda para `expired` em cerca de 5 segundos |
| Termina em `02`, como `10002` | Continua em `waiting_payment` até expirar |

Cada mudança também envia o webhook correspondente ao projeto.

## Confirme uma transação manualmente

Para confirmar uma transação pendente, use o `id` retornado na criação:

```bash
curl --request POST \
  --url https://api.payments.bob.company/api/v1/sandbox/transactions/TRANSACTION_ID/pay \
  --header "Authorization: Bearer $BOB_API_KEY"
```

Esse endpoint aceita somente uma chave `sk_test_`. Ele muda a transação para `paid` e envia `transaction.paid`.

## Cenários mínimos de teste

- [ ] Criar uma transação e apresentar o `pixCode`.
- [ ] Receber e validar `transaction.paid`.
- [ ] Receber `transaction.expired`.
- [ ] Ignorar com segurança uma entrega de webhook repetida.
- [ ] Repetir uma criação com a mesma `Idempotency-Key` sem duplicar a transação.
- [ ] Tratar uma requisição inválida e um timeout.

<Note>
  O campo `isSandbox: true` identifica eventos de teste. Transações de sandbox não aparecem nos dados financeiros de produção.
</Note>
