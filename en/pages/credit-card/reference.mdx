To accept credit cards you **do not** send card data to the Bob API. Number, CVV, and expiry are collected and tokenized in the browser (Bob checkout or Bob.js/Secure Fields) — the API only receives the `btk_...` token.

<Warning>
  Never send raw card data (PAN, CVV, or expiry) to the Bob API. See the [card flow](/en/pages/credit-card/overview) and the [Checkout SDK](/en/pages/sdk/checkout).
</Warning>

## Create (`POST /api/v1/transactions/`)

```json
{
  "customer": { "...": "..." },
  "payment": { "amountCents": 25000, "product": "Pro Plan" },
  "paymentMethod": "credit_card",
  "card": {
    "token": "btk_...",
    "installments": 3,
    "holderName": "JOHN DOE",
    "returnUrl": "https://store.example.com/3ds-return"
  },
  "originDomain": "store.example.com"
}
```

`201` response (card fields):

```json
{
  "success": true,
  "data": {
    "id": "clx7a8b9c0d1e2f3g4h5",
    "externalId": "order_123",
    "status": "waiting_payment",
    "cardBrand": "visa",
    "cardLastFour": "4242",
    "installments": 3,
    "nextActionUrl": "https://3ds.example.com/challenge",
    "nextAction": { "type": "redirect", "url": "https://3ds.example.com/challenge" }
  }
}
```

| Field | Description |
|---|---|
| `card.token` | Opaque single-use Bob token `btk_...` from the browser |
| `card.installments` | Installments 1–12 (default 1) |
| `card.returnUrl` | HTTPS URL after 3DS |
| `cardBrand` / `cardLastFour` | Display-safe fields on create response |
| `nextActionUrl` / `nextAction` | Present when the issuer requires 3DS |

## Read (`GET /api/v1/transactions/{id}`)

Returns the transaction with `paymentMethod: "credit_card"` and common fields. Final outcome arrives via webhook.

## Statuses

| Status | Description |
|--------|-------------|
| `waiting_payment` | Waiting for 3DS or async confirmation |
| `processing` | Payment received, awaiting confirmation |
| `paid` | Payment approved |
| `refunded` | Amount returned |
| `cancelled` / `expired` | Ended without approval |

Do not treat HTTP `201` alone as payment confirmation — use webhooks and/or status polling.
