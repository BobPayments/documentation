Bob Payments processes **credit cards** when the method is **enabled on the project**. For most integrations, use hosted checkout or the embeddable SDK: they load secure fields, tokenize the card, run 3DS, and handle processing.

<Note>
  The card **must be tokenized in the browser**. Your application and the API only receive an opaque `btk_...` token — PAN, CVV, and expiry never pass through the Bob API. See the [Checkout SDK](/en/pages/sdk/checkout) and the [Reference](/en/pages/credit-card/reference).
</Note>

## Choose the integration level

| Level | When to use |
|---|---|
| **Hosted checkout** | Default path. Create a session and redirect the buyer to `checkoutUrl`. |
| **Embeddable SDK** | Keep the buyer on your site and mount Bob checkout inside it. |
| **Direct API (headless)** | Own checkouts: create a tokenization session, tokenize in the browser with Bob.js/Secure Fields, charge with `transactions.create`. |

## Recommended flow

```text
Card in the browser
  -> Bob Checkout / Secure Fields (Bob.js)
  -> btk_... token (single-use, amount-bound)
  -> Bob API (paymentMethod: credit_card + card.token)
  -> nextActionUrl if 3DS · webhook on outcome
```

Card number, CVV, and expiry never pass through the Bob API.

<Warning>
  Never send raw card data to the Bob API. Payloads with PAN, CVV, or expiry are rejected.
</Warning>

## Hosted checkout

Pass `credit_card` in `paymentMethods`:

```bash
curl -X POST https://api.payments.bob.company/api/v1/checkout-sessions/ \
  -H "Authorization: Bearer $BOB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amountCents": 25000,
    "items": [{ "name": "Pro Plan", "quantity": 1, "unitAmountCents": 25000 }],
    "paymentMethods": ["credit_card", "pix"],
    "successUrl": "https://store.example.com/thanks",
    "webhookUrl": "https://store.example.com/webhooks/bob",
    "webhookVersion": "v2"
  }'
```

The session accepts `credit_card` when the method is enabled on the project. Otherwise the API reports that the method is unavailable.

## Embeddable SDK

```tsx
import { BobCheckout } from '@bobpayments/checkout-sdk';

<BobCheckout
  sessionToken={checkoutToken}
  onSuccess={(payment) => navigate(`/orders/${payment.id}`)}
  onError={(error) => showError(error)}
/>
```

## Direct API (tokenize + charge)

1. On the server, create a tokenization session (`POST /api/v1/card-tokenization-sessions/` with `amount_cents`, `currency`, `origin` and required `Idempotency-Key`).
2. In the browser, mount Bob.js/Secure Fields with `id` + `client_secret` and obtain `btk_...`.
3. On the server, charge with `paymentMethod: "credit_card"` and `card: { token, installments?, returnUrl? }`.

If the issuer requires 3DS, the response includes `nextActionUrl` / `nextAction` — redirect the cardholder. The transaction stays `waiting_payment` until the webhook (`transaction.paid` / `transaction.failed`).

With the server SDK: `bob.cardTokenizationSessions.create` then `bob.transactions.create({ paymentMethod: 'credit_card', card: { token: 'btk_...' } })`.

The `btk_...` token is **single-use and amount-bound**. A decline or amount change requires a new session and token. Do not persist or log `client_secret`.

## Public statuses

| Status | Meaning |
|---|---|
| `paid` | Payment approved |
| `waiting_payment` | Waiting for 3DS or async confirmation |
| `processing` | Payment received, awaiting confirmation |
| `refunded` / `cancelled` / `expired` | Terminal outcomes without approval |

Use webhooks and/or status polling for the financial outcome. Do not treat HTTP `201` alone as payment confirmation.
